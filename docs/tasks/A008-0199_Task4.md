## Task Charter

### Goal

Recover a checkpointed unfinished GUI tool turn after session-process loss,
preserving its durable run/session/workspace and runtime turn identities, or
expose uncertainty without replaying effects.

### Primary Deliverable

An existing-coordinator recovery path using validated PlatformStore checkpoints,
a durable pre-effect fence, bounded raw-tail restoration and workspace evidence,
with a real process-replacement continuity regression of at least 100 tool rounds.

### In Scope

- Review the delivered continuation, checkpoint, lease and process contracts.
- Persist the minimal recovery supplement: recent raw rounds, consumed tool IDs,
  interaction sequence and selected route, bound to the existing checkpoint.
- Fence recovery durably before any subsequent tool effect or turn completion;
  cancellation, explicit process stop and host shutdown must not trigger resume.
- Discover the latest valid checkpoint through the existing recovery owner.
  Resume only with unchanged, verifiable workspace/artifact evidence and no
  subsequent potentially effectful operation. Consume recovery eligibility
  atomically and reuse existing queued/lease dispatch; no competing scheduler.
- Compare HEAD, index and working files plus locally referenced artifacts.
  Changed or unverifiable evidence produces an explicit uncertainty reason and
  leaves the run in needs_reconciliation. Opaque external/terminal effects may
  conservatively make recovery unverifiable. No claim of filesystem atomicity.
- Restore completed work as context, never as executable tool calls. Preserve
  source references, recent raw tail, cumulative tool budget and duplicate IDs.
- Retain current memory retrieval/projection and normal post-output completion.
- Document the bounded recovery decision in an active ADR and owning documents.

### Out of Scope

- Automatic replay of tools or unknown effects; recovery of pre-existing
  checkpoints lacking recovery metadata; guaranteed recovery from every crash.
- New client controls, public protocol, scheduler, semantic memory model,
  retention policy, provider routes, dependencies, publication or deployment.
- Changes to completed Task 1–3 archives or ordinary inter-turn continuity.

### Definition of Done

- An actual replacement OS process continues a valid checkpoint under the same
  durable run/session/workspace and runtime run identity, without repeated tools.
- Latest-valid selection and retained source bindings survive database reopen.
- Workspace mutation, missing workspace, unknown effects, stale owners,
  cancellation and explicit stop refuse automatic continuation.
- A deterministic 100+ tool-round run crosses repeated compaction and process
  replacement within a finite measured request ceiling and preserves raw evidence.
- Failed recovery never erases an earlier checkpoint or presents uncertain
  findings as verified current state. Existing effect-review remains usable.
- Tests, documentation, journal, immutable archive and handoff are complete;
  CURRENT_TASK is restored byte-for-byte from its template.

## Decisions and Notes

- Initial review: existing checkpoint rows retain semantic state and durable tool
  event bindings, but not provider raw-tail messages, tool counters or a
  synchronized pre-effect fence. Those are necessary supporting recovery data.
- Automatic continuation is already opt-in via Task 3 pressure configuration.
- No delegation; no external push/publication is authorized or performed.
- Implementation refinement: the real GUI fixture exposed that existing
  direct-dispatch, runtime-timeout and trace wrappers omitted the providers'
  measurement capability. Forwarding that existing capability is a necessary
  checklist step for the frozen real-runtime recovery/measurement proof, not
  new provider support or a replacement budget policy. Embedded-ACME remains
  unmeasured and explicitly unsupported for opt-in automatic continuation.
- Persist only newly compacted source interactions plus the raw tail; previous
  durable bindings are reused. This avoids reprocessing all historical rounds
  for every checkpoint while preserving cumulative source coverage.
- Workspace evidence is conservative and cumulative. Opaque tool effects make
  it unverifiable; private provider reasoning is omitted from recovery storage.
- Final product-contract review: PROJECT_BRIEF's PC clauses are unchanged; its
  only edit links the new bounded ADR. No scope or necessity amendment required.
