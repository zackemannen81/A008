## What landed

An A008 chat transcript for ADR 0019 D5/D7.

- `ChatPane(props: { session })` consumes only the existing `GuiSession`
  members (`status`, `thought`, `answer`, `error`, `prompt`). It renders three
  distinct DOM channels: `data-a008-channel="user" | "thought" | "answer"`.
- Thought is display-only: a collapsible `<details>` block labeled
  "Thought, display only. Not part of the answer." It is never concatenated
  into answer text, in the model or in the DOM.
- Streaming shows a live turn with "Thinking…" before the first answer token
  and "Writing…" while the answer grows. The transcript sticks to the bottom
  unless the reader scrolls up.
- User text is observed by wrapping `session.prompt` on the shared session
  object, restored on unmount. If a later session client exposes a `messages`
  array, `buildChatTranscript` prefers it automatically.
- Canvas-like layout (user right, assistant left, scrollable log,
  `role="log"` + `aria-live="polite"`) with A008 copy only. No OpenHands
  components, no `@openhands/*` import, no PostHog, no telemetry, no provider
  call, no credential.

## Review of the previous run's commit

Read critically rather than trusted. Three findings, all fixed in `70bbc0b`:

1. The claimed "DOM contract" gate did not test the DOM. `chat-transcript.test.ts`
   only exercised the transcript model, so a `ChatPane` that rendered
   `{turn.thought}{turn.answer}` inside the answer node would still have passed.
   Fixed by `chat-pane.dom.test.ts`, which renders the real component and reads
   the markup back. Confirmed by mutation (below).
2. Duplicate assistant turn. The two `useEffect` commit paths in `ChatPane`
   were not idempotent: when a session client clears its buffers *after* a new
   prompt is sent, the finished answer was committed once by the prompt capture
   and a second time by the clear, landing a stale copy below the new user
   message. The current stub never streams, so the defect was invisible until
   A008-0033 lands. Replaced by the pure `chat-history.ts` reducer, which
   commits each turn exactly once and still commits two identical answers as
   two turns. Covered by `chat-history.test.ts`.
3. `emptyStateCopy` was an exhaustive `switch` with no `default`. A sibling
   worker is widening `gui/src/session/types.ts`; adding one status member
   would have broken the GUI build from outside this module. A `default` arm
   now keeps it compiling and rendering.

Also adjusted: the archive under `docs/finished/` claimed a "DOM-contract unit
test" and listed root `npm test` as skipped. Both statements are corrected there
to match what this run actually executed.

## Risks for the operator to weigh

1. `capture-prompt.ts` reads user text by replacing `session.prompt` on the
   shared session object, because the frozen `GuiSession` contract has no
   message list and `gui/src/session/` and `gui/src/composer/` are other
   workers' write scopes. It restores the original on unmount and is covered by
   tests. If A008-0033 returns a frozen session object, the assignment is caught
   and the pane degrades to showing assistant turns only — it does not throw. The
   durable fix is a `messages` array on the session; `buildChatTranscript`
   already prefers one when present, so that switch needs no chat change.
2. This branch was written against the `GuiSession` in `gui/src/session/types.ts`
   at `43d5e3e`. A sibling worker is widening that file additively. The chat
   module reads only existing members and now tolerates a widened `status`
   union, but if that worker lands first, re-run section 1 and 2 after merge.
3. `gui/src/chat/node-test-shims.d.ts` and `gui/src/composer/node-test.d.ts`
   both declare `node:test` and `node:assert/strict`. They coexist today because
   `gui/tsconfig.json` sets `skipLibCheck: true`. A later task that turns
   `skipLibCheck` off, or that adds `@types/node` to the GUI package, should
   collapse the two shims into one shared declaration.
