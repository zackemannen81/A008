## What landed

`useGuiSession()` is the browser client for A008 GUI host protocol v1
(ADR 0019 D4). It connects to `/v1/session`, holds `sessionId`, keeps `thought`
and `answer` in separate buffers, tracks connection status, and exposes
`connect`, `prompt` and `cancel`.

- Client frames carry only `type`, `requestId`, `sessionId`, `text`, `model`.
  A test asserts the key allowlist on every frame the client sends and asserts
  that `authorization`, `apiKey` and `env` never appear.
- `thought` and `answer` are appended to independent buffers and both are keyed
  by `sessionId`, so a frame addressed to another session cannot contaminate
  either. A new prompt clears both buffers before the first frame arrives.
- Unknown server frame types are ignored so the host can add frames later.
  Malformed JSON or a malformed known frame fails the session with a message,
  never a silent partial state.
- One prompt is in flight at a time; a second is rejected rather than queued.
- `cancel()` sends the D4 cancel frame and rejects the in-flight prompt.
- A generation counter discards events from a superseded socket, so `connect()`
  after an error opens a fresh socket without stale handlers firing.

### Published `GuiSession` shape

```ts
export type GuiSessionStatus = "idle" | "connecting" | "ready" | "error";

export interface GuiSessionState {
  readonly status: GuiSessionStatus;
  readonly sessionId: string | undefined;
  readonly model: string;
  readonly thought: string;
  readonly answer: string;
  readonly error: string | undefined;
}

export interface GuiSession extends GuiSessionState {
  connect(): Promise<void>;
  prompt(text: string): Promise<void>;
  cancel(): Promise<void>;
}
```

## Changes made to the previous run's uncommitted code, and why

1. **`#openSession` restructured from `async`/`await` to event-driven.** This
   was a real defect, not a style change. The previous code awaited the socket
   `open` event and only then registered `#pendingConnect` and sent
   `session/new`. Because the continuation after `await` runs in a microtask,
   the pending request was registered one tick too late: a host frame arriving
   in the same turn as `open` was dropped and the connect promise never
   settled. Ten of the nineteen tests deadlocked and the runner hung with no
   output until killed. `session/new` is now sent from the socket `open`
   listener, and `#pendingConnect` is registered before the socket is even
   constructed, so the pending request always exists before any frame can
   arrive. `#waitForOpen` was deleted as dead code.
2. **`settleQuietly` added at the hook boundary.** `GuiSessionClient.connect`
   rejects on a failed handshake, which is the right contract for a
   programmatic caller and is what the tests assert. The only in-app caller is
   `gui/src/settings/settings-pane.tsx`, which does
   `void props.session.connect()` — no catch. An unwrapped rejection would
   therefore become an unhandled promise rejection in the browser console every
   time the GUI host is not running, even though the failure is already shown
   correctly through `status` and `error`. The hook now hands the view a
   `connect` that settles. `settings-pane.tsx` is outside this worker's write
   scope, so the fix is on this side of the boundary. Two tests cover it.
   Reverting is a three-line change in `use-gui-session.ts` if the operator
   prefers the raw rejection.
3. **Magic number `3` replaced with `SOCKET_CLOSED`** in `#detachSocket`.
4. **Two tests added** for `settleQuietly`; the other nineteen are the previous
   run's, unmodified.

Everything else from the previous run was reviewed and kept: `protocol.ts`,
`types.ts`, `node-ambient.d.ts`, the fake WebSocket, and the nineteen original
test cases were correct.

## Risks to weigh before merge

- **No host to talk to yet.** A008-0032 (`src/gui-host/`) is not on `main`, so
  the wire contract is verified against the ADR text and a faked socket, not a
  running server. If the host's frame field names drift from ADR 0019 D4, the
  parser rejects the frame and the session shows an error rather than silently
  mis-parsing — but the first live handshake is still unproven.
- **`settleQuietly` is a deliberate deviation** from the previous run's design,
  made because the only in-app `connect()` caller discards the promise. It is
  described above and is trivially reversible if the operator wants the raw
  rejection to reach the view.
- **`gui/src/session/node-ambient.d.ts` overlaps `gui/src/composer/node-test.d.ts`.**
  Both declare `node:test` and `node:assert/strict` as ambient modules in the
  same `tsconfig` program. `skipLibCheck: true` means the duplicate declarations
  are not reported today and typecheck is clean, but consolidating the two into
  one shared declaration file is worth a small follow-up. Doing it now would
  require editing the composer module, which is outside this write scope.
- **No auto-connect on mount** is a product decision, not an omission. If the
  operator wants the GUI to dial the host on load, that changes the A008-0037
  Connect button's visibility and should be decided with that module's owner.
