## Result

`read_file` returns a section rather than flooding context with an entire large
file. For example, `{path:"src/example.ts",offset:500,limit:30}` requests lines
501–530, subject to the result-byte cap. Content preserves original line endings
and has no inserted line-number prefixes. The whole-file hash enables guarded
`edit_file`; successful edits return a new hash for chaining further changes.

Defaults: 200 lines and 8192 result-text bytes. `offset`, `lines`, `total_lines`,
`next_offset`, `complete` distinguish sections from whole files. A page can end
early to fit the byte limit, but never cuts through a line or UTF-8 character.
Follow next_offset only when more content is needed and compare hashes across
pages. Extremely long lines fail explicitly. Local snapshots are capped at 16 MiB
independently of the model-visible result budget, with a bounded chunked read.

`edit_file` keeps full-file revisions, unique-match checks and approvals, with
uniform LF/CRLF normalization and actionable no-match/multiple/stale diagnostics.
Mixed line endings remain literal. Whole-file line-ending conversion and concurrent
filesystem transactions are not supplied. Terminal/Git have per-call output caps
under runtime ceilings; their descriptions steer toward scoped output. All other
tools and explicitly enabled MCP capabilities remain available.
