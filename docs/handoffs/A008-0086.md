Status: Complete

## Delivered

The standalone tool permission dialog now offers `Reject`, `Allow once`, and `Allow all`. Selecting `Allow all` approves the current request and stores an in-memory GUI-client policy for that connected session. Later `tool/permission` frames for the same session are answered with the existing `{ allow: true }` protocol response without reopening the dialog.

The policy is deliberately not persisted. Dispose, end-session, reconnect, or a newly opened session resets it. The host/ACP wire contract remains boolean and engine/native-client permission ownership is unchanged. Model text, retrieved content and tool arguments cannot set the policy.
