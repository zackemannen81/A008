# A008-0193 handoff

Completed 2026-09-27.

## Outcome

The memory engine, retrieval, state/claim lifecycle, reinforcement, supersede,
commit and persistence semantics are unchanged.

Only the worker/userMessage-facing memory envelope changed. Each retrieved item
now exposes:

- `id`
- optional `semanticAddress`
- `label` — the readable label already carried by the retrieved record
- optional `history`
- optional `provenance`

The worker envelope no longer substitutes a state value such as `true`, `false`
or another bare `currentState` value for the record's readable knowledge label.

Dialogue extraction deliberately remains separate: it reuses the same retrieval
result without a second read, but retains the engine-oriented `currentState` or
`claim` representation required for state updates and exact reinforcement.
