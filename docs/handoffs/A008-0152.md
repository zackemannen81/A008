## Delivered

- Removed the implicit `unknown catalog provider -> NVIDIA` coercion.
- Execution providers are explicit: OpenAI, NVIDIA, kie, OpenRouter, Groq,
  Google and OpenCode; unsupported providers fail before network dispatch.
- Compatible user models persist exact provider, normalized base URL and API
  style across save/reload.
- Added validated OpenAI-compatible Chat-Completions execution for current
  ZeroCostRadar OpenRouter, Groq, Google Gemini and OpenCode Zen routes.
- Direct/reference mode uses the published ACME Chat-Completions adapter;
  embedded ACME 0.1.6 composes the same routes through explicit
  `compatible[]` entries.
- Native OpenAI remains on ACME's native Responses route. A Radar
  `openai-responses` compatible-provider route remains blocked; this task does
  not downgrade OpenAI to Chat Completions.
- Provider settings now own write-only `OPENROUTER_API_KEY`, `GROQ_API_KEY`,
  `GEMINI_API_KEY` and `OPENCODE_API_KEY`, with renderer-visible
  configured/source metadata only.
- ZeroCostRadar model registration now accepts only a route key at
  `POST /v1/catalog/zero-cost/models`; the host re-fetches and validates the
  current public feed before persisting the exact route.
- The legacy NVIDIA catalog mutation refuses compatible-provider injection.
- Radar Add eligibility is derived from exact supported provider/base URL/API
  style rather than provider-name guesses.
- A008 remains on `acme-engine ^0.1.6`; no ACME source/release change was
  needed. Current docs were corrected from stale 0.1.5 labels.
