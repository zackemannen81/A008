## Delivered

`npm run platform-admin` runs `src/platform/admin-cli.ts`. The four commands are `info`, `list-conversations --project`, `get-run --run`, and `cancel-run --run --expected-revision`. Origin is `--origin` or `A008_PLATFORM_ORIGIN`. The device token is only `A008_DEVICE_TOKEN`, sent once as a bearer through `createPlatformV3Client` for the three resource commands. `info` does not send it. The script does not load `.env.local`, accept a credential flag, URL credential, or prompt, and it does not open a database. There is no reconcile, import, grant, revoke, or backup command.

`info` prints `available` and the capability names returned by the host. A successful `available: false` exits 0. Resource calls against an unavailable platform exit `NOT_FOUND`. Missing credentials exit `UNAUTHENTICATED`. A lost response exits `TRANSPORT_ERROR`. None of those paths retry. `cancel-run` performs one cancel request per invocation.

Device credentials stay in the existing `DeviceRegistry` used by the host. The test mints one credential there; it does not add a store.

## Known limitations

- Inspection and one cancel only. No conversation or run creation, reconcile, import, grant, revoke, or backup.
- A lost cancel response is not retried, so the operator must `get-run` before deciding whether to cancel again. The host may already have applied the cancel.
- `info` with `available: false` exits 0. It is a successful public read, not an SDK error.
- The CLI does not mint credentials. Use the existing device CLI and `A008_DEVICE_TOKEN`.
- Backend limits still apply: text-only runs, no tools, no public reconciliation mutation.
