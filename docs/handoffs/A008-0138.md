## Delivered

- Stable `commandId` is required on mutating V2 session commands and remains distinct from request/turn/session/server/model-execution identity.
- Read-only `session/inspect` and `session/control { action: "inspect" }` remain command-ID-free.
- `src/gui-host/v2-command-receipts.ts` owns a process-local `(principal, commandId)` registry using a canonical SHA-256 digest of action/project/session/payload.
- Same ID + same canonical payload returns the existing running/terminal receipt and does not re-enter the mutation path.
- Same ID + changed payload returns `COMMAND_CONFLICT`.
- Running prompt receipts carry the stable `turnId`.
- Failed command attempts retain their structured failure receipt so an identical retry observes the same failure without provider/tool re-execution.
- Terminal receipts retain for five minutes, cap at 1,024 per principal and never evict running/unexpired receipts to admit another mutation.
- Expired/unknown/foreign-principal lookup returns `COMMAND_UNKNOWN`.
- Authenticated `GET /v2/projects/{projectId}/commands/{commandId}` exposes bounded receipt metadata only.
- Public discovery advertises `session.command-receipts`, `session.command-idempotency` and the receipt limits.
- Runtime GUI truth surface now lists receipt/idempotency as implemented and leaves reconnect/resume + restart uncertainty pending.
- No durable exactly-once, reconnect/resume or restart-survival guarantee was added.

## Security / failure semantics

- Receipt storage never retains raw mutation payloads; canonical content is represented only by its digest plus bounded receipt metadata.
- Dynamic project-binding detail is normalized to a public generic error before receipt storage.
- Receipt lookup reuses authenticated principal/project/session capability authority; another principal receives `COMMAND_UNKNOWN`, not existence information.
- This is process-local bounded idempotency. Process loss remains uncertainty and belongs to A008-0140.
