## Delivered

Normal dialogue memory prompts now follow the simpler librarian contract.

- Retrieval scope treats its maxima as ceilings and asks for the smallest useful
  label set rather than filling generic project/status/planning labels.
- Memory context explicitly treats current-state items as applicable knowledge
  and historical items, when present, as prior state.
- Dialogue extraction distinguishes retrieved item `id` from `evidenceId`;
  reinforcement must copy the exact retrieved item id.
- State updates must copy a current-state semantic address from the same
  retrieved baseline and the structured attribute binding must resolve to the
  same slot.
- Metadata guidance is sparse: tags/domains/entities are emitted only when they
  improve future retrieval for that artifact.
- Relation classification is shorter and same-address driven:
  restatement/supersede/conflict cannot cross semantic addresses; runtime owns
  Current State, History, canonical identity and lifecycle.
- Intake deterministically rejects mismatched state-update addresses before
  relation classification/commit.

The source-ingestion-only `POST_OUTPUT_KNOWLEDGE_ANALYZER_INSTRUCTION` remains
unchanged by design.
