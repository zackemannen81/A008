## What landed

ADR 0019 D3–D4 host protocol v1, exactly the documented frames:

- `GET /health` -> `{ ok: true, name: "A008-gui-host" }`
- `GET /v1/models` -> `{ models: [{ id, name }] }`
- `POST /v1/shell` `{ command }` ->
  `{ stdout, stderr, exitCode, timedOut, truncated }`, produced by the existing
  `runTerminalCommand` from `src/tools/terminal.ts` in the GUI host process
  cwd. The host does not reimplement execution.
- `WS /v1/session`: client `session/new` / `prompt` / `cancel`; server
  `session/new/ok` / `thought` / `answer` / `prompt/ok` / `error`. ACP
  `agent_thought_chunk` becomes `thought`, `agent_message_chunk` becomes
  `answer`.
- `gui/dist` is served when it exists; traversal outside the root is refused.

The host spawns the existing `A008-acp` stdio server. One subprocess serves
every renderer, and each WebSocket owns only the session ids it created, so one
renderer cannot prompt or cancel another's session.

`NVIDIA_API_KEY` and memory settings are read from `process.env`, forwarded to
the ACP subprocess, and never placed in a frame or an HTTP body.

## What I changed in the previous worker's code, and why

The carried-over code was sound and already typechecked; the following were
real defects or gaps.

1. **No cross-origin guard on a shell endpoint.** `POST /v1/shell` executes an
   arbitrary command in the host cwd, and the host had no `Origin` check and no
   content-type requirement. A page on any origin could have reached it with a
   cross-origin HTML form (a simple request that needs no CORS preflight), and
   any origin could have opened `/v1/session` because WebSockets are not
   subject to CORS. Added `src/gui-host/origin.ts`: a request whose `Origin`
   header is present and neither same-origin nor loopback is refused (403) on
   every HTTP route and on the upgrade, and `POST /v1/shell` requires an
   `application/json` content type (415 otherwise). Requests with no `Origin`
   (curl, Node `fetch`) and the loopback Vite dev proxy still work.
2. **Every ACP failure reached the GUI as "Internal error".** The ACP SDK
   reduces an unhandled agent error to a generic JSON-RPC `Internal error` and
   moves the real text to `data.details`. `acpFailure` in `acp-bridge.ts` now
   recovers that text. Verified against the spawned fake ACP: the frame is now
   `synthetic ACP failure`, not `Internal error`.
3. **A host that could not start `A008-acp` said only "ACP connection
   closed".** The bridge now keeps a bounded tail of the subprocess stderr and
   appends its last line to the failure, so a missing key reports
   `ACP connection closed: A008-acp failed: [redacted] is required for NVIDIA
   chat.`
4. **HTTP failure bodies did not carry the field the GUI reads.** The merged
   A008-0036 client (`gui/src/terminal/run-shell-command.ts`) reads `message`
   from a failure body; the host only sent `error`, so the GUI would have shown
   the bare status text. Failure bodies now carry both.
5. **Host shutdown was not deterministic.** `close()` ignored a bridge that was
   still being created, and `server.close()` waited on `fetch` keep-alive
   sockets — one test spent 3.0s there. `close()` now awaits the pending bridge
   and calls `server.closeAllConnections()`; that test now takes 11ms.
6. **Upgrade rejections could be truncated.** `socket.write(...)` followed by
   `socket.destroy()` can drop the unflushed response; changed to `socket.end`
   in `server.ts` and `websocket.ts`.
7. **Gate coverage was incomplete.** `cancel` and the error path only ran
   against an in-process injected bridge, so `acp-bridge.ts` itself was
   untested on those paths. Added cancel and error tests over the spawned stdio
   ACP transport (the error test also proves the subprocess survives a failed
   turn and the session still works), plus cross-origin refusal tests for HTTP
   and WebSocket and unit cases for the origin guard. 10 tests became 16.

## Risks the operator should know before merging

1. `gui/vite.config.ts` proxies `/v1` without `ws: true`, so the dev proxy will
   not upgrade `/v1/session`. A008-0033 must connect directly to
   `ws://127.0.0.1:8787/v1/session`, or that config — owned by another task —
   needs `ws: true`. Not changed here because `gui/` is out of scope.
2. Wire redaction removes the literal tokens `NVIDIA_API_KEY` and
   `authorization` from assistant text as well as from credentials. That is
   what ADR 0019 D6 asks for, and it means an answer that legitimately
   discusses those tokens is shown redacted. The smoke output above is an
   example: `[redacted] is required for NVIDIA chat.`
3. The origin guard allows any loopback origin so the Vite dev server on
   `localhost:5173` works. If the host is ever bound to a non-loopback
   interface, a same-origin browser is still allowed and everything else is
   refused, but a shell endpoint on a routable interface is a deployment
   decision that deserves its own review. The default bind stays `127.0.0.1`.
4. `src/gui-host/` is a new top-level source directory that
   `docs/FILESTRUCTURE.md` does not yet map. That file is outside this write
   scope.
5. ACP sessions are not released when a renderer disconnects; the ACP agent has
   no session-close request in this SDK usage, so a long-lived host accumulates
   session state in the subprocess. Not a defect for this slice, but a
   candidate for the backlog.
