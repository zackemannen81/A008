## Risks the operator should weigh before merging

1. **Release is disconnect-driven only.** A host whose renderer never
   disconnects cleanly — a hung tab, a killed browser that leaves the socket
   half-open until TCP notices — still holds its sessions until the process
   exits. An idle timeout or a reaper is a separate concern and was kept out of
   scope deliberately.
2. **`closeSession` throws on an unknown session.** That is intentional and
   matches every other session-scoped method on this agent, but it means a
   client that double-closes gets an error rather than a no-op. The host never
   double-closes, because it clears `ownedSessions` after releasing.
3. **`openSessionIds()` is a new public method on `A008AcpAgent`** that exists
   for observability. It returns identities only, never session state.
4. **Agent Server is also a client of this agent.** The new capability is
   additive and a dedicated test asserts every previously-read `initialize`
   field is unchanged, but the operator path was not re-run live.
