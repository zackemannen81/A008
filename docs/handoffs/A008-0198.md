# A008-0198 — Handoff (complete)

## Delivered

- Automatic live-turn context pressure is opt-in through existing runtime budgets; 0/0 remains disabled.
- After every completed tool round, ChatSession measures the complete next provider request through the selected transport's real serializer.
- The first exact measurement binds the route identity for the live turn. Any later route drift fails closed before dispatch.
- OpenAI, NVIDIA, KIE and ACME expose exact serialized-body measurement at their actual provider serialization boundary.
- At soft pressure, one tool-free bounded reducer request may run per completed-operation boundary on the selected route.
- Reducer output is strict JSON and must pass the canonical A008-0196 run/provenance/state-byte validator.
- The validated state and raw source interactions are persisted through the A008-0197 PlatformStore bridge before candidate projection adoption.
- Candidate context is rebuilt from the authoritative current-turn base, validated continuation state and configured recent raw tail; it is re-measured and adopted only if it fits the hard ceiling.
- Repeated tool rounds may compact repeatedly within the same logical run. Canonical conversation history and raw execution evidence remain unchanged.
- Missing measurement, invalid bounds, route drift, reducer/checkpoint failure or an oversized rebuilt request fails closed and never authorizes replay.
- Process-loss checkpoint discovery/resume/replay is still Task 4.
