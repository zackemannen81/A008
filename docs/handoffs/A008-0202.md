## Result and use

In GUI MCP settings, edit a server and turn off **Strict tool arguments (default)**
to choose non-strict for that server. Add per-tool overrides using the original
MCP tool name. Saved configuration is visible in the server list. Start a new
GUI chat to reliably pick up the new catalog; active tool sessions retain theirs.
No actual user settings were changed by this implementation.

API/catalog fields: optional `strict` boolean and `toolStrict` map. Override wins
over server default, which defaults to true. ACP transports policy via
`_meta["a008/toolPolicy"]`. The shared ACME mapper passes explicit booleans.
The owner's acme-engine 0.1.7 upgrade is included; the separate directly imported
Chat Completions adapter was upgraded from 0.1.4 to pinned 0.1.7 as well.

Original MCP argument validation precedes approval/execution in both modes.
Only strict accepts the existing optional-null omission sentinel. Existing
session binding, containment/replay checks, permissions and call budgets remain.
Invalid arguments return the existing failure result for bounded model correction.
No fallback to non-strict, new retry mechanism or structured-output change.
