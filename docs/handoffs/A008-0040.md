## The finding the operator should read

`test/knowledge-model/evidence.test.ts` and `state-history.test.ts` were absent
from `test:core` and had **never run**. 20 cases. Both passed on first
execution, so nothing was broken — but nothing had been checking, and
`evidence.test.ts` is where `ingest()`'s own tests live. A change to `ingest()`
could not have been honestly verified while its test file sat outside the gate,
which is why wiring both in was folded into this task rather than deferred.

A sweep confirmed those were the only two: 43 test files on disk, 41 referenced
before, 43 after.

This is the same defect class A008-0039 closed for the GUI. The root fix is not
a straight copy — see the backlog entry for why `dist/` not being cleaned makes
a glob riskier here than it was there.

## Risks the operator should weigh before merging

1. **The default preserves existing behaviour, so nothing stored changes.** Any
   record written before this change keeps its meaning. The change is additive.
2. **`ContentKind` is still undecided for uploads.** `classifySpeech()` picks a
   kind from the content when the caller does not pass one, so a vision
   description will land in whatever `classifySpeech` infers — probably
   `dialogue_assertion`. The relation is now correct; the kind is not yet. This
   will need deciding before an upload path ships, and it is the third time it
   has surfaced.
3. **`speaker` is the caller's responsibility and is not validated beyond
   non-empty.** Passing the uploading user as speaker for a model-written
   description would still misattribute it, and could let it through the
   `user-assertion-v1` activation gate. The parameter is now available to do
   this correctly; nothing forces a caller to.

## Next recommended operator action

Merge, then decide `ContentKind` for uploads before any vision path is built —
that is now the only thing standing between this parameter and a correct upload
ingest.
