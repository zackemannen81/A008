## Delivered

Opt-in local `/v3` composition in the GUI host. `GuiHostOptions.platformPath` or `A008_PLATFORM_PATH` opens one platform SQLite file outside the repository, distinct from semantic memory, and holds `acquireRuntimeLease(path, "platform")` for the process lifetime. Without that path, `GET /v3/info` is `{ protocolVersion: "a008.platform.v3", available: false, capabilities: [] }` and no platform database is opened. V1/V2 routes are unchanged.

The tenant is the fixed id `local`. Resource routes require the existing V2 PIN or device credential. Only the `session` capability is mapped. An engine or model bearer is not app auth. `owner_browser` can dispatch only while the host PIN profile is enabled. Resource lookup searches registered, authorized projects and returns the same `NOT_FOUND` for foreign and unknown ids.

`PlatformStore.lookupRunReceipt` is read-only and uses the store's canonical digest. Identical `run.create` replays before model and capacity checks. A changed payload is `COMMAND_CONFLICT`. New work is text-only: the already-owned project runtime gets `openSession({ model, conversationSeed })` and exactly one `turn`, with no tools. The seed excludes that run's new user message. A committed assistant answer is kept if post-output memory fails; memory is recorded separately and does not cause another provider call. Dispatched work with no committed assistant stays unknown and becomes `needs_reconciliation` after lease recovery. There is no public reconciliation mutation.

Disconnect does not cancel accepted work. Shutdown stops new dispatch before aborting turns and does not close project runtimes underneath those callbacks. A failed bind releases the platform lease.

## Config and defaults

| Knob | Env | Default | Bounds |
| --- | --- | --- | --- |
| Database | `A008_PLATFORM_PATH` or `GuiHostOptions.platformPath` | unset (unavailable) | absolute file outside the repo, not semantic memory |
| Active runs | `A008_PLATFORM_MAX_ACTIVE_RUNS` | 4 | 1..32 |
| Nonterminal per project | `A008_PLATFORM_MAX_NONTERMINAL_PER_PROJECT` | 100 | 1..100 |
| Nonterminal backend | `A008_PLATFORM_MAX_NONTERMINAL` | 256 | 1..256 |
| Lease | `A008_PLATFORM_LEASE_MS` | 30000 | 50..300000 |
| Renew | `A008_PLATFORM_RENEW_MS` | 5000 | 10..60000 and less than the lease |
| Turn timeout | `A008_PLATFORM_TURN_TIMEOUT_MS` | 120000 | 50..120000 |
| Shutdown drain | `A008_PLATFORM_SHUTDOWN_DRAIN_MS` | 10000 | 0..120000 |
| Scan | `A008_PLATFORM_SCAN_MS` | 1000 | 10..60000 |
| Response bytes | `A008_PLATFORM_MAX_RESPONSE_BYTES` | 8388608 | 1..8388608 |

Fixed limits: JSON body 1 MiB, prompt 65536 UTF-8 bytes. Renewal must be shorter than the lease, and active/per-project caps cannot exceed the backend nonterminal cap.

Available capabilities, only when the database is open: `durable-conversations`, `durable-runs`, `command-receipts`, `event-polling`, `background-text-runs`, `restart-uncertainty`.

## Known limitations

- Text-only. No tools, durable approval, migration, multi-tenant, or public reconciliation resolution.
- Pre-dispatch `failRun` can leave `memoryStatus: pending` because the store records a memory outcome only after a committed answer.
- Response-byte overrides can be lowered for tests but not raised above 8 MiB. A create that already committed can still return `CAPACITY_EXCEEDED` if its snapshot exceeds the ceiling; the row remains.
- `needs_reconciliation` is terminal for this slice. Operators cannot clear it through HTTP.
- Old workspace chats are not imported.

A missing committed assistant after dispatch stays unknown until lease recovery marks `needs_reconciliation`. There is no public reconciliation mutation. See `docs/platform/BACKEND.md`.
