## Result

The GUI previously coalesced only in-flight permission requests. Once a POST
finished, an older live/view snapshot could submit the same decision again and
flash the host's "This permission is no longer pending" error.

DurableChatClient now remembers successful decisions by run ID and permission ID
for its instance lifetime. Both observer and refresh hide resolved prompts, and
the sending path suppresses repeated decisions. Allow and reject are treated
equally. Successful manual decisions clear only the matching current prompt.
New IDs/runs remain independent; failed HTTP requests are not remembered as
success. Existing concurrent coalescing and allow-all behavior remain.

No host/ACME changes, no blanket hiding of conflicts, and no cross-client
exactly-once guarantee. A new client instance after page reload has no historical
confirmation cache; durable execution/permission authority remains in the host.
