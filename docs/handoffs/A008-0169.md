## Delivered

Dialogue post-output extraction now receives the exact same-turn knowledge
projection used for provider context together with the normalized user message
and final provider response. No second retrieval occurs after generation.

Projected context items preserve stable item identity and, where owned by the
read path, evidence identity, semantic address and current state. The provider
context intentionally carries bounded knowledge identity; runtime/project/session
routing identity, retrieval scores/reasons, lifecycle control data and provider
reasoning remain excluded.

The dialogue extractor returns four explicit semantic buckets:

- `new_knowledge`
- `state_updates`
- `relation_updates`
- `reinforcements`

Existing retrieved knowledge is not staged again merely because it is repeated.
Material reuse/reaffirmation can instead reference the exact retrieved artifact
for lifecycle reinforcement. State changes at the same semantic address remain
state-update candidates rather than duplicates.

Retrieval/admission is now lifecycle-read-only. Explicit reinforcement is
post-output and exactly-once per turn/evidence occurrence. Source/document
extraction retains its existing source-only analyzer contract.

## Commit path retained

The existing cost/latency path is preserved:

```text
provider response
  -> one knowledge extraction call
  -> staged proposal batch
  -> direct explicit reinforcement write(s), when present
  -> one batch relation-classifier call
  -> local sequential batch commit
```

The normal model-backed path still implements `classifyBatch`; it does not fan
N extracted proposals into N classifier calls. The existing deterministic
fallback remains only for injected/legacy classifiers without batch support.

Commit-time dedupe, merge, state/history reconciliation, relation persistence and
canonical semantic ownership remain in A008. ACME behavior and packages are
unchanged.

A coordinator wiring defect discovered during verification was fixed:
`PostOutputMemoryCoordinator.stagingInput()` previously sanitized away
`retrievedContext`; it now defensively carries the same-turn projection into
staging.

## Important invariants after this task

- Current state/history semantics are unchanged.
- Retrieved knowledge identity is semantic identity, not execution authority.
- Retrieval alone does not reinforce.
- Repetition can reinforce without creating duplicate knowledge.
- State update and dedupe are separate decisions.
- Extraction-time baseline comparison does not replace commit-time dedupe.
- A008 owns semantics; ACME owns execution only.

## Known limits

- The model still decides whether an existing item was materially reused or
  reaffirmed; runtime validates that reinforcement can only target an artifact
  actually present in the same retrieved projection.
- Items without a reinforceable evidence identity cannot receive direct
  lifecycle reinforcement from this new path.
- The broader existing relation/reconciliation machinery is retained; this task
  does not simplify or replace it.
- No Platform V3 migration or cross-session pending-turn overlay is included.
