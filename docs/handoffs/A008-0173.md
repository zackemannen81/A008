## Observed failure

The owner-local log contained seven initial new claims, followed by a turn
where the new colour of an already-known file produced only reinforcement.
Thus the initial memory write succeeded; the later property was never proposed.
The projection also copied query tags/entities onto every retrieved item,
making old knowledge appear labelled with the new query's property. This is a
confirmed metadata defect and a plausible contributor to the model omission;
the trace alone cannot establish the model's internal causal reasoning.

## Delivered

- Projection carries each stored record's own tags and domains. Query entities
  are no longer represented as item applicability scope. No per-record scope
  exists on this read representation, so item scope is empty.
- Domains survive provider serialization, intake normalization and the model
  adapter, preserving the same-turn baseline.
- Dialogue extraction explicitly distinguishes entity familiarity from an
  established property/value. Source-grounded new attributes are structured
  knowledge; runtime still resolves their canonical addresses.
- Reinforcement cannot silently accept an invented address for a retrieved
  target without that address. Omitting the optional address remains valid.
- Worker context and shared single/batch relation prompts distinguish metadata,
  old descriptions and new properties. No state/lifecycle/storage redesign.
