## Delivered

- Ordinary V2 transport loss detaches the existing owned session instead of destroying it.
- Detach first interrupts active work, waits for terminal settlement and denies pending tool permissions.
- Each V2 session receives an opaque 256-bit resume capability returned by `session/new` and successful `session/resume` only.
- Detached state survives for an initial 45-second process-local lease.
- `session/resume` requires the same authorized principal/project/session and matching opaque capability, rejects second writers, rebinds the existing session and returns an authoritative A008-0132 snapshot boundary.
- Wrong principal/project/session/capability, explicit close and expired lease fail deterministically.
- Resume never replays transient thought/answer output, provider execution, tool execution or stale approvals.
- Device revoke/expiry uses hard termination and never creates resume authority.
- Discovery advertises `session.reconnect-resume` and `sessionResumeLeaseMs: 45000`.
- Runtime capability UI leaves only restart uncertainty as the remaining Stage-4 gap.
- No durable/background/restart survival guarantee was added.

## Security / ownership

- Resume capability is never put in URLs, ordinary snapshots, command receipts or provider/model payloads.
- Session ID alone is not resume authority.
- The same V2 session owner remains authoritative; no parallel recovery/runtime owner was introduced.
- Revoke/expiry hard-terminates rather than detaching.
- The lease is deliberately same-process only. Process restart destroys session/resume authority and is handled as uncertainty by A008-0140.
